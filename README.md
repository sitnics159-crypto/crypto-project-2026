# Crypto Project 2026

Веб-прототип для изучения публичных данных Ethereum Sepolia и справочных котировок BTC/ETH. Интерфейс публикуется как статический сайт GitHub Pages; запросы данных Sepolia обслуживает отдельный API-сервис Render.

**Сайт:** [sitnics159-crypto.github.io/crypto-project-2026](https://sitnics159-crypto.github.io/crypto-project-2026/)

## Статус проекта

Работающий прототип доступен для проверки. Коммерческий выпуск зависит от согласования условий использования данных и выполнения [чек-листа выпуска](docs/RELEASE_CHECKLIST.md).

- [Проверки и публикации на GitHub Actions](https://github.com/sitnics159-crypto/crypto-project-2026/actions) показывают результаты проверки страницы, детерминированных тестов и браузерных проверок с реальными API.
- [Политика безопасности](SECURITY.md) описывает порядок передачи сообщений об уязвимостях.
- Основная ветка `main` публикуется в GitHub Pages; API-сервис Sepolia размещён отдельно на Render.

## Возможности

- **Проверка транзакции Sepolia:** статус, участники, тип операции, сумма ETH, комиссия, блок, время и доступные события переводов токенов. Краткое пояснение строится по полученным полям, без генеративной модели.
- **Проверка адреса Sepolia:** баланс тестового ETH, тип адреса, метки Blockscout и недавняя история транзакций с подгрузкой следующих страниц.
- **Балансы ERC-20:** после поиска адреса нажмите «Загрузить балансы». Запрос проходит через API-сервис проекта к Blockscout Sepolia. Суммы отображаются с доступной точностью, а при ошибке можно повторить загрузку.
- **Переводы ERC-20:** входящие и исходящие фильтры, постраничная загрузка и экспорт загруженных записей в CSV. CSV формируется в браузере из уже загруженных записей; экспорт не означает, что получена полная история адреса.
- **Аналитический отчёт:** формирует сводку по загруженным переводам выбранного фильтра. Кнопка «Сохранить PDF» открывает системный диалог печати браузера, где пользователь может выбрать сохранение в PDF. Отчёт явно указывает, что охватывает только загруженные записи, а не всю историю адреса.
- **Метки риска:** предупреждения показываются, если Blockscout явно пометил адрес как потенциально мошеннический. Такая метка не доказывает мошенничество, а отсутствие метки не подтверждает безопасность.
- **Рыночная сводка:** котировки BTC/USD и ETH/USD, изменение примерно за последние 24 часа и часовые графики. Изменение рассчитывается относительно первой доступной часовой свечи в запрошенном 24-часовом интервале; если свечи недоступны, показатель не подменяется изменением с начала календарного дня.
- **Ссылки на поиск:** результаты можно открыть по URL с параметром `tx` или `address`.

## Архитектура и источники данных

- **Интерфейс:** статические файлы `index.html`, `token-balances.mjs` и модули отчёта, публикуемые GitHub Pages.
- **Sepolia API:** браузер обращается к `crypto-project-2026.onrender.com/api/sepolia/...`. Сервис Render проверяет допустимые маршруты и параметры, добавляет серверный ключ Blockscout и пересылает только разрешённые GET-запросы к фиксированному API Blockscout для сети Sepolia (chain ID 11155111). Ключ Blockscout не должен попадать в клиентский код.
- **CORS:** API разрешает браузерный доступ с origin опубликованного GitHub Pages сайта. Это ограничение браузерного доступа, а не механизм аутентификации пользователей.
- **Ограничение запросов:** текущий обработчик использует лимит начала запросов к Blockscout в памяти процесса, если не подключён внешний общий ограничитель. При нескольких экземплярах сервиса такой локальный лимит не является общим для всех экземпляров.
- **Рыночные данные:** [Kraken ticker API](https://docs.kraken.com/api-reference/market-data/get-ticker-information/) и [OHLC API](https://docs.kraken.com/api-reference/market-data/get-ohlc-data/) вызываются браузером напрямую для справочных котировок и часовых свечей.
- **Источники Blockscout:** [документация API](https://docs.blockscout.com/devs/apis) — транзакции, адреса, балансы и события токенов.

Рыночные котировки являются отдельной справочной функцией и не относятся к данным блокчейна Sepolia. Источники могут временно ограничивать частоту запросов, возвращать неполные данные или быть недоступны.

## Поисковые данные и ссылки

Браузер отправляет введённый публичный хеш или адрес в API-сервис Render; сервис передаёт разрешённый запрос в Blockscout Sepolia. Сам идентификатор также сохраняется в URL страницы. Если поделиться ссылкой, получатель увидит этот идентификатор. Страница задаёт политику `no-referrer`, чтобы браузер не передавал полный URL страницы в заголовке Referer. Запросы котировок к Kraken выполняются отдельно и не содержат поискового хеша или адреса. CSV формируется в браузере из загруженных переводов.

В текущем API нет пользовательской авторизации или личного кабинета. Не вводите конфиденциальные данные: поиск предназначен только для публичных адресов и хешей.

## Ограничения и безопасность

- Данные адресов и транзакций относятся к тестовой сети Sepolia; тестовый ETH не имеет стоимости ETH основной сети.
- Котировки Kraken справочные, могут отличаться от других площадок и не являются инвестиционной рекомендацией.
- Сайт не подключает кошелёк, не отправляет транзакции, не принимает приватные ключи или seed-фразы.
- API-сервис принимает только разрешённые GET-маршруты и проверяет формат параметров; он не предоставляет произвольный прокси к Blockscout.
- Пояснение транзакции основано на данных обозревателя и не устанавливает намерения участников или полный смысл взаимодействия со смарт-контрактом.
- Метки риска отражают данные Blockscout и не являются самостоятельным доказательством мошенничества или безопасности.
- CSV и аналитический отчёт охватывают только загруженные записи выбранного фильтра; для анализа следующих страниц их необходимо загрузить отдельно.
- Автоматические проверки и успешная публикация не заменяют полный независимый аудит безопасности, ручную проверку доступности и проверку условий поставщиков данных.

## Локальная проверка

Для быстрой проверки вёрстки запустите статический HTTP-сервер из корня репозитория:

```sh
python -m http.server 8000
```

Затем откройте `http://localhost:8000`. Это локальное превью интерфейса; рабочий API ограничивает CORS опубликованным GitHub Pages origin, поэтому локальный браузерный просмотр не является подтверждением доступности live API. Автоматические live-проверки выполняются отдельным workflow GitHub Actions.

## Публикация

GitHub Actions публикует сайт в GitHub Pages только из ветки `main`. Workflow также можно запустить вручную из `main`; запуск из других веток не выполняет публикацию. Отдельные проверки контролируют статическую страницу, тесты и интеграцию с live API. Workflow Pages скачивает опубликованные `index.html` и `token-balances.mjs` и сравнивает их побайтно с артефактом текущего запуска.

После публикации откройте [пример адреса Sepolia](https://sitnics159-crypto.github.io/crypto-project-2026/?address=0xd482cCc8EC97e9cA7a365F2403bf7f228aD149A0), нажмите «Загрузить балансы» и убедитесь, что появилась строка `FAUCET` с адресом контракта и суммой. Баланс тестового адреса может меняться.
