# MVP: публичная аналитика Ethereum Sepolia

## Цель

Создать статический веб-прототип, который помогает изучать публичные данные тестовой сети Ethereum Sepolia: проверять транзакции и адреса, просматривать переводы ERC-20 и понимать доступные сведения без подключения кошелька.

Дополнительно прототип показывает справочную рыночную сводку BTC/USD и ETH/USD из публичного API Kraken. Рыночные данные не относятся к сети Sepolia и не используются для оценки риска блокчейн-адресов.

## Для кого

Для пользователей, которым нужно быстро разобраться в публичной транзакции или активности адреса Ethereum, не изучая вручную необработанные ответы API.

## Основные сценарии

### 1. Проверка транзакции

1. Пользователь вводит хеш транзакции.
2. Интерфейс проверяет формат хеша.
3. Прототип запрашивает публичные сведения Blockscout для Sepolia.
4. Показывает доступные данные: статус, отправителя, получателя, сумму ETH, комиссию, блок, время, тип операции и доступные события переводов токенов.
5. Формирует краткое пояснение только на основе полученных полей и предоставляет ссылку на запись в обозревателе.

### 2. Проверка адреса

1. Пользователь вводит адрес Ethereum.
2. Прототип получает сведения об адресе из Blockscout Sepolia.
3. Показывает баланс тестового ETH, тип адреса и доступные метки источника.
4. Показывает недавнюю историю транзакций с постраничной загрузкой.
5. Показывает только переводы с типом ERC-20 (не смешивает их с ERC-721/ERC-1155), с фильтрами входящих и исходящих записей, постраничной загрузкой и экспортом уже загруженных записей в CSV. Для определения количества использует decimals из события или метаданных токена Blockscout; если decimals недоступен, показывает исходное значение без выдуманного пересчёта. Самоперевод, где адрес совпадает с отправителем и получателем, обозначается отдельно и не попадает одновременно в фильтры «Входящие» и «Исходящие».

### 3. Предупреждения о метках риска

Если Blockscout явно пометил адрес как потенциально мошеннический, интерфейс показывает предупреждение и указывает, что это метка источника, а не доказательство мошенничества. Отсутствие такой метки не подтверждает безопасность адреса.

### 4. Рыночная сводка

Прототип получает публичные котировки BTC/USD и ETH/USD из Kraken, показывает доступное изменение цены примерно за последние 24 часа и строит графики по часовым свечам. Если данные для расчёта или графика недоступны, интерфейс не должен подставлять вымышленные значения.

### 5. Ссылки на результаты

Поиск транзакции или адреса можно открыть по URL с параметром `tx` или `address`. Секретные данные и содержимое кошелька в ссылку не включаются.

## Источники данных

- Blockscout Sepolia API — публичные данные транзакций, адресов, балансов и переводов токенов.
- Kraken public Ticker API — справочные котировки BTC/USD и ETH/USD.
- Kraken public OHLC API — часовые рыночные свечи.

Источники могут ограничивать частоту запросов, возвращать неполные данные или быть временно недоступны. Прототип должен показывать понятное сообщение об ошибке и позволять повторить запрос.

## Требования к безопасности и точности

- Использовать для блокчейн-проверок только публичные данные Ethereum Sepolia.
- Не подключать кошельки и не запрашивать адреса доступа к кошелькам, приватные ключи или seed-фразы.
- Не подписывать и не отправлять транзакции, не управлять средствами и не хранить пользовательские активы.
- Явно обозначать тестовую сеть; тестовый ETH не является ETH основной сети.
- Разделять исходные данные обозревателя и пояснительный текст.
- Не приписывать участникам транзакции намерения, которые нельзя установить по публичным полям.
- Не представлять метку Blockscout как доказанный факт мошенничества или отсутствие метки как гарантию безопасности.
- Не представлять рыночную сводку как инвестиционную рекомендацию.

## Обработка ошибок

Интерфейс должен понятно обрабатывать:
- пустой ввод;
- неверный формат хеша или адреса;
- транзакцию или адрес, не найденные в Sepolia;
- временную недоступность API и ограничение частоты запросов;
- тайм-аут и неполный ответ источника;
- отсутствие отдельных полей, событий, переводов или рыночных свечей.

Неизвестные значения нужно обозначать явно, а не заменять предположениями.

## Критерии готовности

MVP считается готовым, когда пользователь может:
1. Проверить хеш транзакции Sepolia и увидеть доступные сведения и краткое пояснение.
2. Проверить адрес Sepolia и увидеть доступные сведения и недавнюю историю.
3. Просмотреть доступные переводы ERC-20, отфильтровать их и экспортировать загруженные записи в CSV.
4. Понять ограничения меток риска и рыночных данных.
5. Открыть сохранённый URL поиска транзакции или адреса.
6. Получить понятную ошибку при некорректном вводе или сбое источника.
7. Использовать прототип без подключения кошелька и предоставления секретных данных.

## За пределами текущего MVP

- Основная сеть Ethereum и другие блокчейны.
- Подключение кошельков, подписание и отправка транзакций.
- Хранение средств, приватных ключей или seed-фраз.
- Автоматическое установление мошенничества или юридической квалификации адреса.
- Глубокий аудит смарт-контрактов и гарантированное определение смысла каждой операции.
- Персональные аккаунты, серверная история поиска и синхронизация пользовательских данных.
- Генеративные AI-объяснения.
- Прогнозы цен и инвестиционные рекомендации.

Пояснения в текущем прототипе формируются программными правилами на основе доступных полей, а не внешней генеративной моделью.
